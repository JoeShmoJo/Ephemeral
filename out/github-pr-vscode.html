    01What a pull request is

    A proposal: "here are some commits on a branch — look at them, then put them into main."

    It is not a Git feature; it is a GitHub feature wrapped around two branches. The PR is a page showing the difference between your branch and main, collecting comments and test results, ending in a merge button.

    branch → commit → push → OPEN PR → review → MERGE → delete branch

    Nothing touches main until the merge. Until then the branch is a sandbox — push half-finished work to it as often as you like.

    Why bother when you are the only developer

    • You review your own diff. Reading every changed line in one screen catches the debug print you left in, the file you did not mean to commit, the password in a config.
    • main stays releasable. If a branch turns out badly, close the PR and delete it. Nothing to undo.
    • Tests run before the merge. A red check stops a bad merge instead of reporting it afterwards.
    • The reasoning is written down. In six months the description explains why, which the code never does.
    • It is the habit every team expects. Practising alone costs nothing.
    tipWorking solo, keep branches small and short-lived — one change, one PR, merged the same day. A branch that lives three weeks becomes a merge conflict.

    02Setup, once

    Install and sign in

    • Ctrl+Shift+X ▸ search GitHub Pull Requests, published by GitHub ▸ Install.
    • A GitHub icon appears in the Activity Bar down the left edge. Click it ▸ Sign in.
    • Nothing happens? Use the Accounts icon at the bottom of the Activity Bar ▸ Sign in with GitHub.
    noteThis sign-in is separate from the credential Git uses to push. Authorising GitHub twice on a new machine is normal — once for the extension, once on your first git push.

    Check the repository is connected

    The extension only appears when the folder you have open is a Git repository with a GitHub remote.

    git remote -v

    Two settings worth changing

    SettingWhy
    Git: AutofetchVS Code notices when GitHub has moved ahead, so you are not working from a stale main. Ctrl+, then search autofetch.
    Default Merge MethodSet to squash if you want each PR to land as one tidy commit. Search default merge method.

    04Open a PR, start to finish

    The loop to keep open the first few times.

    1 — Start a branch

    Click the branch name in the bottom-left corner ▸ Create new branch… ▸ name it after the change ▸ Enter.

    git switch -c fix-login-crash
    warningBranch before you make the change where you can. Already edited files? No problem — uncommitted edits follow you onto the new branch.

    2 — Commit

    Ctrl+Shift+G, type a message, press Ctrl+Enter. VS Code stages everything if nothing is staged.

    git add .
git commit -m "fix the crash when the login form is empty"

    3 — Publish the branch

    The blue button in Source Control now reads Publish Branch. That creates the branch on GitHub, which is what makes a PR possible.

    git push -u origin fix-login-crash

    4 — Create the pull request

    Ctrl+Shift+P ▸ GitHub Pull Requests: Create Pull Request, or the button VS Code offers as soon as the branch is published. The panel asks for four things:

    FieldWhat to put
    BaseThe branch to merge into — almost always main.
    Merge / BranchThe branch the change is on — the one you just published.
    TitleSame style as a commit message: fix crash when the login form is empty.
    DescriptionWhy, not what — the diff already shows what. Note anything you are unsure about.
    tipNot finished? Use the arrow beside Create ▸ Create as Draft. Checks still run, but it cannot be merged until you press Ready for review — ideal for moving work in progress between machines.

    5 — Read your own diff

    Expand the PR ▸ Files Changed. Click each file for a red/green diff. Read every line before merging your own work — this is the entire point of the exercise.

    6 — Merge

    Bottom of the PR tab: pick a method, confirm, and tick Delete branch.

    MethodWhat lands on main
    Create a merge commitEvery commit from the branch plus a merge commit. Full history, messier graph.
    Squash and mergeOne commit containing the whole change. Tidy main — the good default working solo.
    Rebase and mergeEach commit replayed onto main, no merge commit. Linear, but no record of the branch.

    7 — Get back to main

    The merge happened on GitHub, so your PC does not know about it yet.

    git switch main
git pull
git branch -d fix-login-crash

    05Reviewing

    Look without changing anything

    Click a PR in the GitHub view. The description tab opens with the conversation, the checks and the file list; clicking a file opens a read-only diff. Your working folder is untouched.

    Check it out to run it

    To actually run the code: Checkout on the PR tab, or Ctrl+Shift+P ▸ Checkout Pull Request. When you are done, Exit Review Mode puts you back on the branch you came from.

    git switch fix-login-crash   # the same thing by hand
git switch main              # and back
    warningCommit or git stash your own work first. VS Code refuses the switch if uncommitted changes are in the way.

    Comment on a line

    • Open the file diff, hover the line number, click the +.
    • Add Comment posts immediately. Start Review holds comments back so several post together.
    VerdictMeans
    CommentNotes, no judgement. Neither blocks nor unblocks the merge.
    ApproveGood to merge. GitHub will not let you approve your own PR — merge it directly instead.
    Request changesBlocks the merge until a later version is approved.

    Answer comments and push a fix

    Reply in the thread, then Resolve conversation. To change the code, commit and push to the same branch:

    git add .
git commit -m "address review comments"
git push

    The PR updates itself. There is no "new PR" step — a pull request tracks the branch, so every push to it shows up automatically.

    06Checks and conflicts

    Reading the checks

    SymbolMeaning
    Yellow dotStill running. The merge button waits.
    Green tickPassed. Safe to merge.
    Red crossFailed. Details opens the log on GitHub with the failing step expanded.

    Fix it like any other change: commit to the branch, push, checks run again.

    "This branch is out of date with main"

    Something else merged first. Bring main into your branch — in VS Code that is Ctrl+Shift+P ▸ Git: Merge Branch… ▸ origin/main.

    git fetch origin
git merge origin/main
git push

    A conflict inside a PR

    GitHub refuses to merge. Resolve it on your PC, not on the website:

    • Run the merge above. Conflicted files appear in Source Control under Merge Changes.
    • Open each one. VS Code shows Accept Current Change / Accept Incoming Change / Accept Both above the conflict, or Resolve in Merge Editor for a three-pane view.
    • Current is your branch. Incoming is main.
    git add .
git commit -m "merge main into fix-login-crash"
git push
    tipMerge main into a long-running branch every day or two. Small conflicts caught early beat one enormous conflict at merge time.

    07Worth knowing

    Link a PR to an issue

    Put a closing keyword in the description and GitHub closes the issue on merge. Typing # in the description brings up a searchable list.

    Closes #14
Fixes #14
Resolves #14

    Create an issue from code

    Select a line ▸ right-click ▸ Create Issue From Selection. The issue links back to the exact line. A TODO comment can be turned into one the same way.

    Protect main so the habit sticks

    On GitHub: repository ▸ Settings ▸ Branches ▸ Add rule ▸ branch name main ▸ tick Require a pull request before merging. A direct push to main is then rejected and you have to use a PR.

    PRs from the terminal

    GitHub's own CLI, for when VS Code is not open.

    winget install --id GitHub.cli -e
gh auth login
gh pr create --fill
gh pr status
gh pr checks
gh pr merge --squash --delete-branch

    09When it will not behave

    SymptomFix
    No Create Pull Request buttonThe branch is not published. git push -u origin BRANCHNAME. Also check you are not sitting on main — you cannot open a PR from main into main.
    GitHub view is empty, or asks you to sign in foreverAccounts icon ▸ sign out of GitHub ▸ sign in again. Still looping: close VS Code, reopen, retry.
    GitHub view does not appear at allThe open folder is not a Git repository with a GitHub remote. Check git remote -v, and make sure you opened the project folder itself, not its parent.
    Checkout is refusedUncommitted changes are in the way. Commit, or git stash, then retry.
    PR shows commits you did not expectWrong base, or the branch started from an old main. Merge origin/main in and check the base on the PR tab.
    Merge button greyed outA check is running, a review requested changes, or there is a conflict. The PR tab says which.
    Pushed, but the PR did not updateYou pushed a different branch than the PR tracks. git status names the current one.

    I committed to main by mistake

    Nothing is lost — the commits just need a branch of their own.

    git switch -c fix-login-crash
git switch main
git reset --hard origin/main
git switch fix-login-crash
git push -u origin fix-login-crash
    dangerThat git reset --hard throws away anything on main that is not on GitHub — which is what you want here, because the first line already copied those commits onto the new branch. Run git log --oneline -5 on the new branch first and confirm they are there.

    10One-page summary

    Every change, start to finish

    git switch -c short-name-for-the-change
git add .
git commit -m "what this change does"
git push -u origin short-name-for-the-change

    Then Ctrl+Shift+P ▸ Create Pull Request ▸ read the diff ▸ merge ▸ tick Delete branch.

    Afterwards

    git switch main
git pull

    Answering review comments

    git add .
git commit -m "address review comments"
git push

    Branch out of date

    git fetch origin
git merge origin/main
git push
